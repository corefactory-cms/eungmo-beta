# 응모수첩 웹 베타

[휴대폰에서 응모수첩 열기](https://corefactory-cms.github.io/eungmo-beta/)

공식 이벤트의 경품, 응모 방법, 주최 측 발표 위치를 모아서 봅니다. 응모는 주최 측에서 하고, 내 응모와 당첨 여부는 본인이 표시합니다. 응모·당첨·수령 기록은 사용하는 브라우저에 저장되므로 브라우저 데이터를 삭제하면 사라집니다. 기기 간에는 동기화되지 않습니다.

## 운영자가 공고를 올릴 때

1. [현재 배포된 공고](https://corefactory-cms.github.io/eungmo-beta/events.json)와 [리서치 요청문](tools/리서치_요청.txt)을 이용해 공식 응모처와 결과 안내를 확인하고 JSON 파일로 저장합니다.
2. Windows에서 `tools/공고_올리기.cmd`를 열고 파일을 고릅니다. Python 3과 이 저장소 쓰기 권한으로 로그인한 GitHub CLI가 필요합니다. 다른 운영체제에서는 `python3 tools/publish.py 공고.json`으로 실행합니다.
3. 추가·수정할 제목을 확인하고 `y`를 입력합니다. 도구는 기존 공고와 ID별로 합쳐 게시합니다. 같은 필드를 동시에 수정한 게시가 있으면 GitHub가 이전 버전 쓰기를 거부합니다. 최신 내용을 보고 다시 실행합니다.
4. [배포 상태](https://github.com/corefactory-cms/eungmo-beta/deployments)를 확인합니다. 배포 뒤에는 사이트를 열거나 돌아오면 새 목록을 읽습니다. 열어 둔 화면에서도 약 1분마다 확인하며, 직접 새로고침할 수도 있습니다.

새 공고에는 기존 행과 같은 필드 구조를 사용합니다. 이미 있는 공고는 ID와 변경할 필드만 보내도 됩니다. 공고가 끝나도 기록을 다시 찾을 수 있도록 ID를 유지합니다. 운영자 업로드 파일에는 공개 행사 정보만 적습니다.

## 데이터

- `docs/events.json`은 모든 사용자가 받는 공개 공고입니다. `sourceUrl`은 주최 측 공고, `entryUrl`은 응모처, `announcementUrl`은 추후 발표를 확인할 곳, `resultUrl`은 실제 게시된 결과 원문입니다.
- 날짜는 한국 시간 기준입니다. 발표 여부를 확인할 수 없는 경우 날짜나 결과 주소를 추측해서 채우지 않습니다.
- Pretendard 글꼴 라이선스는 [OFL](docs/OFL.txt)에 있습니다.
